## Non-negotiable slice rules

- Keep `main` launchable at every interruption boundary. The remote
  `codex/continuous-overhaul` compatibility ref may mirror an accepted `main`
  checkpoint; a lagging local ref is non-authoritative and is fast-forwarded
  only at a safe branch boundary.
- Prefer one reusable data contract over eight or thirty-six bespoke scripts.
- Simulation/host owns legality and outcomes; presentation owns only readable
  interpretation.
- Every attack costs Flux; movement costs Stamina only where authored.
- Every refusal explains physical state, resource, cooldown, slot, or authority.
- Preserve protocol/wire IDs or migrate versions explicitly.
- Run focused tests first, then full deterministic tests, Windows source/import
  boots, packaged boot, and relevant Farflow processes before a green checkpoint.
- Never stage/delete `node_modules/` or `scripts/firewall.ps1`.
- Execute O0–O14 from `.agent/OPTIMIZATION-IMPLEMENTATION.md` only at their
  assigned seams; optimizations may not become a detached rewrite or reorder
  the first-eight chemistry acceptance path.
- Execute `.agent/DELIVERY-EFFICIENCY.md` as the development loop: scenario and
  selected suites for fast feedback, Fast at structural seams, Full at every
  checkpoint, and Release only for package acceptance.
- Fix movement or visual regressions immediately, but add no new technique or
  broad retuning before C9 evidence; every ordinary frame preserves the order
  champion → threat → interaction → world → decoration.
- Apply `docs/PLAYER-EXPERIENCE-OVERHAUL.md` to every slice: a new mechanic must
  create a readable decision, compose with existing languages, expose an honest
  cost/counter and teach failure; more options or spectacle alone are not value.
