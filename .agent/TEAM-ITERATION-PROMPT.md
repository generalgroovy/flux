Act as FLUX's integration lead and create six focused subagent workstreams:
runtime, gameplay, artwork, map, usability and characters. Work against the
authoritative Godot checkout and preserve every existing user-owned change.
The user explicitly requests implementation, repeated testing and a playable
state. Use original artwork and systems; named reference games supply broad
principles of response, spacing, readable patterns and temporary matter.

## Integration contract

Read the live backlog, newest memory and
`docs/CORE-GAMEPLAY-AND-CHEMISTRY-REVISION.md`. First restore a green Full gate
for the in-progress protocol-38 control/high-jump changes. Then assign bounded,
non-overlapping file ownership, no more than three workers at once. Queue the
remaining streams as slots free. Workers must deliver implemented changes,
focused evidence, limitations and an exact handoff; never mark conceptual work
as playable. The lead alone merges checkpoints, changes shared protocol/schema,
edits shared bootstrap/test registration, runs shared-log suites and publishes.

Choose a complete observable outcome per slice. Keep source import and boot
working; stop a failing branch of work and repair it before expanding. Exercise
real production paths, not duplicate toy simulations. Use isolated logs for
independent diagnostics; never run scripts/test.ps1 concurrently. Run one Full
gate after integration and a real Farflow smoke for authority changes. Publish
only a green reviewed checkpoint, preserve Windows launch and safe shutdown,
and record exactly what has and has not been verified.

Character implementation remains a continuing workstream until the requested
cast is playable. A roster row is not a completed character; never promote
unreviewed concept art, fabricated stats or a name-only clone. Prefer reusable
ancestry/body recipes and composition to bespoke controllers.

## Cross-stream design

Movement creates an opening; spell form shapes a lane; the element leaves finite
material; pair chemistry creates a readable temporary decision. All attacks
cost Flux; locomotion actions cost Stamina. Reduce visual/physical speed together
only where measured, and keep ordinary movement useful under slow effects.
Holds buy height/distance without extending immunity. Keep current normalized
eight-way controls, free aim and body travel-facing animation.

After the completed grid presentation, implement first-eight deposits lasting
2-5 seconds with owner/cast identity and a finite shared Burst budget. Build
Steam first, then all 36 symmetric Level 1 pairs, each with a distinct spatial
effect, motion, counter, boundary and cleanup. Share validated primitives;
retain immutable worldbone, no vault, no recursive reactions or material
drift/grip until their later acceptance. Late joiners must receive persistent
material correctly; packet pressure must never hide active dangerous state.

Active release scope is Windows with eight-player lobbies and 120 Hz simulation.
Stress experiments may exceed that count but do not advertise an untested
supported capacity or promise 120 FPS on arbitrary hardware. Preserve lower
effect-density settings and diagnose simulation, rendering and transport costs
separately. Installer trust and public internet routing need their own proof.

## Required handoff after every slice

Record observed improvement, changed files, exact executed checks and results,
what remains open, and the next small task in the repo. Keep README and
implementation order truthful. The lead runs the latest accepted game for the
user at the next review boundary. Follow the planned chemistry acceptance
playtest pause; do not use endless iteration as permission to skip review.
